# Domain docs

Before exploring, read the root `GLOSSARY.md`, or `GLOSSARY-MAP.md` if present, plus ADRs relevant to the work in `docs/adr/`.

If these files do not exist, proceed without flagging their absence. Create them when `/domain-modeling` resolves project terms or decisions.

Use glossary terms in issues, specs, code, and reviews. Surface conflicts with relevant ADRs instead of silently overriding them.

This is a single-context repository. Keep the glossary at the root and ADRs in `docs/adr/`.
